# Repository layout

Target: the root of `oven-sh/bun` (read live on 2026-11-15 with `gh api repos/oven-sh/bun/contents/`): a flat root of manifests and a few directories (`bench`, `completions`, `docs`, `packages`, `patches`, `scripts`, `src`, `test`, `tools`). A root entry stays only when a Bun precedent or a reader that requires the path justifies it. A reader is a tool or code that opens the path; it is proven with `git grep -n -F <name>` before every decision. Moves use `git mv` and every reference is rewritten in the same commit. No archive: git is the history.

Decisions: keep, move, merge, purge. Status: done (commit in git log), pending, or blocked (reason).

## Brand

Target: `docs/logo` and `docs/icons` of `oven-sh/bun` (read live on 2026-11-15 with `gh api repos/oven-sh/bun/contents/docs/logo` and `.../docs/icons`): the generated brand files are committed under `docs`, one logo set and one folder of icons with an `ecosystem/` subfolder. Bun keeps no brand source in the repository; here the source sits with the design tokens it produces.

| Path | Role | Argument | Status |
| --- | --- | --- | --- |
| `docs/logo/` | `logo.svg`, `logo.png`, `logo-mono.svg` (currentColor), `logo-with-wordmark-dark.svg`, `logo-with-wordmark-light.svg` of the primary organisation, plus `<org>.svg` and `<org>-wordmark-{light,dark}.svg` per organisation | Bun file names; generated by `ay brand build`, never edited by hand. Text is outlined with the brand font, every file has a `viewBox` and an accessible `<title>` | done |
| `docs/icons/` | one tile per `[[type]]` of `brand.toml` (crate, package, app, infra, third-party, skill), `glyphs/<type>.svg` in `currentColor`, `ecosystem/<product>.svg` | the global types of the monorepo that `scripts/catalog.ts` reads; same layout as Bun `docs/icons` | done |
| `docs/badges/` | static README badges, no badge service | read by `README.md` and `scripts/catalog.ts` | done |
| `packages/design/brand/` | source: `brand.toml` (single source of the seed, organisations, products, types and the web stages), `src/` SVG templates, `web/gpu.ts`, `brand.just`, `LICENSE`; `gen/` build tree (icon sets, symbols, fonts, images, 3D), `gen-cache/` and `inputs.lock.json` for the third-party inputs | `packages/design` owns the tokens and `build.ts` reads `brand.toml`, so a brand edit and its tokens change in one place. Readers proven with `git grep -n -F packages/design/brand`: `packages/design/src/build.ts`, `packages/assets/src/brand-inputs.ts`, `packages/assets/src/zukan.ts`, `packages/deploy/src/m3.ts`, `src/ui/kit/src/brand`, `src/ay` (icon resources) | done |
| `assets/` | removed | its content moved as above; the remaining `assets/` strings are other tools' on-demand paths (`packages/assets` library and dist, `.github/workflows/assets.yml`) | done |

Generator: `ay brand build` (`just brand` on fr1 builds everything; `ay brand build --no-web --deploy` needs only resvg, so any host builds the SVG, PNG and ICO outputs and copies the site icon set to `apps/aphrody/public`), then `ay brand check`. `bun scripts/catalog.ts` renders the READMEs, `docs/reference/catalog` and the aphrody.com catalog page from the manifests, and `bun scripts/catalog.ts profile <id>` the GitHub profile READMEs (`scripts/catalog.config.json`).
