# Conformance

Compatibility is measured, not claimed. Each of the 11 suites below is an upstream test suite or schema, pinned to a commit in `conformance/upstreams.toml` (commits, never branch names). `ay conformance [--fetch] [suite...]` (crate `test/conformance`) downloads the listed paths as a `gh` tarball (no git) into the ignored `conformance/upstream/<suite>/` and writes `conformance/results/<suite>.json`. Upstream sources are never committed.

Status: no suite runner exists yet (`run` in `test/conformance/src/lib.rs` returns an empty report: total 0). Fetching and the result format are implemented; the per-suite execution is not.

## Policy

- A pin is bumped by a dedicated change that updates `conformance/upstreams.toml`; branch names are rejected as refs.
- Each suite has an expected-failures file, `conformance/expected/<suite>.txt` (one test id and one reason per line, frozen per pin).
- Result file: `{ suite, upstream_commit, aphrody_commit, target, total, passed, failed, skipped, blocked, duration_ms, by_dir: { <dir>: { total, passed } } }`; `aphrody_commit` comes from `APHRODY_REVISION` (`unknown` when unset).
- `ay conformance channels [platform]` writes `third_party/chrome-channels.toml` (Chrome Stable, Beta, Dev, Canary).
