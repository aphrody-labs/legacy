# Axum feature matrix and the Shenron host port

Cargo features were read from the forks (`Cargo.toml` of each crate). "Shenron host" is the TypeScript API host (`apps/shenron/packages/api/src/server/index.ts`, `src/http.ts`), which `crates/shenron-api` replaces route group by route group.

What is new on the forks' main branches, which crates.io does not have yet:

- **axum 0.9-dev:**
  - `ListenerExt::limit_connections`.
  - `serve::ConnectionLifetimeLimits` (MaxConnectionAge with jitter and grace).
  - hyper's 30 s header read timeout applied by `serve`.
  - `TCP_NODELAY` on accepted connections.
  - `sse::Event::raw`.
  - `MethodRouter::method_filter`.
  - `serve::Executor`.
  - Breaking: nested fallbacks merged, `tower-log` no longer a default feature, `serve` output type.
- **tower-http main:** `CorsLayer::validate()`, and `ServeDir`/`ServeFile` honoring `If-Range`.
- **tower-http 0.7 modules:** `csrf` (the Go 1.25 scheme on `Sec-Fetch-Site` and `Origin`, no token state), `metrics::in_flight_requests`, and `on_early_drop` (observes client disconnects).

## Order of the next route groups

1. **Shared HTTP layer first**, so every later group inherits it: `ApiError`, CORS, CSRF, rate limit, public cache with ETag and 304, client IP, trace. Its golden cases are `data/api/fixtures` entries recording CORS and `ETag` headers. Add those headers to `RECORDED_HEADERS` of `packages/api/scripts/api-fixtures.ts`.
2. **Wiki** (`/api/public/wiki/*`, read-only PostgreSQL), then the **VFS** (`ServeDir` plus SQLite), then **account, favorites and watch progress** (cookies and session), then **chat** (SSE and WebSocket).
3. **Front proxy:** route the `OPERATIONS` paths to the `shenron-api` binary (Infra). Then delete the TypeScript of each group and run `just migrate-ratchet`.
