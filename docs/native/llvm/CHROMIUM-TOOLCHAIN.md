# One toolchain with Chromium: clang, lld and rustc on LLVM 24 (2026-11-15)

Owner rule: src builds with the toolchain Chromium ships, so C, C++, Rust and WebAssembly share one LLVM and
cross-language LTO works (`docs/native/llvm/UNIFIED-TOOLCHAIN.md` section 1). The pin is the newest
`third_party/toolchain-<milestone>.toml`; `bun scripts/toolchain.ts` and `rust-toolchain.toml` follow it.

## The pin

From `third_party/toolchain-160.toml` (Chromium prebuilts of tag 160.0.8157.0, `tools/clang/scripts/update.py` and
`tools/rust/update_rust.py`; the canary and dev channels of `third_party/chrome-channels.toml` pin the same revisions,
stable is still on the 157 pair):

| Part                                    | Version                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| clang, lld, llvm-*, clang-tidy          | clang 24.0.0git (llvm-project c3223914, `llvmorg-24-init-17044-gc3223914-1`)                           |
| rustc, cargo, clippy, rustfmt, rust-src | rustc 1.101.0-nightly (41b321963 2026-10-29), cargo 1.101.0-nightly (31d3246e0), LLVM 24.0.0          |

The upstream LLVM release 23.1.5 (2026-11-03) is older than the 24.0.0git of Chromium's pair: the rule keeps
Chromium's, never the older release. The previous pair (157: clang 86922d51, rustc 1.100.0-nightly 2026-09-09) is gone from
the manifest; `scripts/toolchain.ts install` replaces a stale unpacked revision.

## How it is installed

`bun scripts/toolchain.ts install` downloads the host's packages from Chromium's public bucket (`source_url`), checks
`source_sha256`, unpacks them under `~/.local/share/aphrody/toolchain/<milestone>/{clang,rust}` (`$AY_TOOLCHAIN_DIR`
overrides) and runs `rustup toolchain link chromium-<milestone> <rust>`. `status` prints clang, lld and rustc and fails
when one is not the manifest's revision; `env` prints CC/CXX/AR, the LLVM tools and the cross-language LTO `RUSTFLAGS`
(Linux: clang + `-fuse-ld=lld`; Windows: clang-cl + lld-link, Chromium's Windows package has no `clang` driver); `bin`
prints the directory for `PATH` (`>> $GITHUB_PATH` in CI). The packages repacked as content-addressed `.tar.zst` are on R2
(`aphrody-chromium/toolchain/<milestone>/`, used by the factory, `src/chromium/factory`).

Unpacking is not compiling: the PC holds the toolchain for rust-analyzer and clippy and still compiles nothing.

## Facts of the package that decide the linker

- Chromium's rust package carries no `rust-lld` and no `gcc-ld`: rustc links through the `cc` driver, which is GNU
  `gcc` + `ld.bfd` on a stock Linux host. lld comes only from the clang package (`ld.lld`, `lld-link`, `wasm-ld`).
  `.cargo/config.toml` names `rust-lld.exe` for `x86_64-pc-windows-msvc`, which this toolchain does not have either:
  see BUILD-SCIENCE.md for the linker rows measured on this pair.
- The clang package holds `llvm-profdata`, `llvm-cov` (package `llvm-code-coverage`) and `llvm-objdump`
  (`llvmobjdump`) of the same revision as rustc: PGO profiles and coverage data of Rust and C are read by tools
  of their own LLVM. It holds no `llvm-bolt`, no `llvm-size` and no `clang-format` (`clang-tidy` is a package of its own).

## Exceptions, stated and not hidden

- **Alpine musl containers** (`infra/docker`): Chromium ships std for `x86_64-unknown-linux-gnu` (and the Windows host)
  only, no musl std. The images keep `nightly-2026-11-12` (LLVM 23) through `RUSTUP_TOOLCHAIN` until a `-Zbuild-std` musl
  build with the Chromium toolchain is proven.
- **Windows binary**: cross-compiled on fr1 with `cargo xwin` and `-Zbuild-std=std,panic_abort` from the toolchain's
  rust-src (no prebuilt windows-msvc std in the Linux package). The dist release (`release.yml`, generated by dist, also
  macOS which has no package in the manifest) is not switched.
- **The bun fork** (`third_party/bun`) is its own workspace and keeps `nightly-2026-09-15` (LLVM 23) until bun is
  ported to LLVM 24 (`UNIFIED-TOOLCHAIN.md` section 2).
- **clang-format** is not in Chromium's packages: the C-core format check uses the apt.llvm.org release on the runner.
