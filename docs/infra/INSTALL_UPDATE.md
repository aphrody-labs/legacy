# Install and update

How `ay`, the toolchain around it and the published assets are installed and kept current on the workstation and on the hosts. The command list is live: `ay up --help`, `ay self-update --help`.

| Piece | Source | Command |
| --- | --- | --- |
| `ay` releases | [`dist-workspace.toml`](../../dist-workspace.toml), [`release.yml`](../../.github/workflows/release.yml) | push a `v<version>` tag |
| `ay` self-update | [`src/ay/src/self_update.rs`](../../src/ay/src/self_update.rs) | `ay self-update [--check] [--version X]` |
| Toolchain manifest | [`infra/up/tools.toml`](../up/tools.toml) and the overlays in `infra/up/tools.d/` | `ay up --list` |
| Installer | [`src/up`](../../src/up) | `ay up`, `ay up --check`, `ay up <tool>...` |
| Provider wiring | `src/up/src/setup.rs` | `ay up --setup` |
| Workstation bootstrap | `src/up/src/bootstrap.rs` | `ay up --bootstrap` |
| Host schedule | [`infra/up/systemd/ay-up.*`](../../infra/up/systemd) | daily, user units |
| Asset manifests | `src/up/src/assets.rs` | `ay up --assets <dir> [--release <label>]` |

## Releasing `ay`

`ay` is the one workspace member that [dist](https://github.com/axodotdev/cargo-dist) builds: `dist-workspace.toml` disables dist for every package and `src/ay/Cargo.toml` opts back in. Bump the version in the root `Cargo.toml` and the `ay` pin in `tools.toml`, check with `dist plan`, then push the tag. The workflow is generated by `dist generate`; re-apply its manual patches after regenerating it (they are listed in the workflow diff, not here).

## Manifest and installer

`tools.toml` lists each tool with a pinned version, its executables, a version probe and one source (`github`, `url`, `bun`, `installer`, `ubi`). The lookup order is `--manifest`, `$AY_TOOLS_MANIFEST`, `<repo>/tools.toml`, then the copy embedded in the binary, which hosts without a checkout use. Versions marked `lock` come from `src.lock.json`.

- States: `ok`, `ahead`, `outdated`, `missing`, `unknown`, `n/a`. `ay up --check` exits 1 on `missing` or `outdated`.
- The installer writes only under the user's home (`~/.local/bin` by default, `AY_BIN_DIR` overrides) and refuses system directories.
- sha256 is verified whenever upstream publishes it; `ubi` entries carry no checksum, so move a tool to `github` when integrity matters.
- A running executable is replaced by rename, so `ay up` can update `ay` itself.

## Hosts

The user units in `infra/up/systemd/` run `ay up` daily. Fleet bootstraps read the same manifest (`infra/fleet/bootstrap/`, `just fleet-bootstrap <role>`).
