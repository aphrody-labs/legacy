# Automations as libraries

apps/auto keeps its shell (API routes, UI, worker); its domain logic is consumed as libraries.

| Library | Language | Content | Consumers |
| --- | --- | --- | --- |
| `packages/automate` (`@aphrody/automate`) | TypeScript | workflow definitions, node catalog, expressions, executor with injected services, templates, n8n import; 30 tests with the sources | apps/auto (api, worker, web, services, client), apps/web, `ai-os automate`, the TUI |
| `src/modele` (`aphrody-modele`) | Rust | commercial document model and totals shared with `@auto/domain` | apps/auto crates (`auto-docs`, `auto-facturx`, `auto-ffi`, `auto-fichiers`) |

Front ends in this repository:

- CLI: `ai-os automate list | run <template> | models [policy]`.
- TUI: `ai-os automate tui`.
- Web: `apps/web` page `/automations/`, generated by `apps/web/build.ts` from the library.
- ai-router (aphrody-labs/open, release in `packages/ai-os/config/open-libraries.json`): `ai-os automate models` lists the offers the router would use for an automation's AI node.

Proofs are in `docs/automate/proofs/`: `cli-*.txt`, `tui-automations-*.png`, `web-automations-*.png`.
