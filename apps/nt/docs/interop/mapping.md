# Mapping node-api-dotnet → Bun / .NET primitives, bottlenecks and fixes

References: [node-api-dotnet.md](node-api-dotnet.md) (`microsoft/node-api-dotnet@0483aa01`), [bun-lowlevel.md](bun-lowlevel.md) (`aphrody-labs/bun@4b8463ee`), [dotnet-lowlevel.md](dotnet-lowlevel.md) (`dotnet/runtime@42656136`, .NET 11.0.0 GA 2026-11-10). Node for comparison: `nodejs/node@67e45e4a87` (main, 2026-11-12, read through gh api). Prefixes: `nad:` node-api-dotnet, `bun:` Bun fork, `rt:` dotnet/runtime, `node:` nodejs/node.

## 1. Three paths

| Path                                | Principle                                                                                                                   | State                                                                                                                                                                                               |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. Node-API addon (today)           | NativeAOT `.node` of node-api-dotnet loaded by Bun's `process.dlopen`                                                       | Structurally compatible: the 140 imported symbols are defined and exported by `bun.exe`; TSFN present. Never tested under Bun (CI `nad:.github/workflows/build.yml:15-16` = Node only)              |
| B. Direct bun:ffi ("native" target) | NativeAOT `NativeLib=Shared` library exporting blittable `[UnmanagedCallersOnly(EntryPoint)]`, opened by `bun:ffi` `dlopen` | No Node-API or env: typed calls compiled by JSC (`bun:system/jsc/bindings/JSCFFIBridge.cpp:65-97`, engine outside the repository). Limited to scalars/pointers; objects, strings and lifetimes by hand |
| C. Hybrid                           | Path B for hot paths (numbers, buffers), path A for objects, classes, promises                                              | Recommended: the same NativeAOT `.dll` can export `napi_register_module_v1` and flat C symbols                                                                                                      |

## 3. Bottlenecks and limits measurable in the code

1. **Node-API per-call cost, double allocation**: on the .NET side a `JSValueScope` (class) per call + 2 `napi_get_cb_info` + 2 `SetSynchronizationContext` (`nad:JSValue.cs:1362`, `nad:src/NodeApi/JSCallbackArgs.cs:34-46`, `:75-84`, `nad:src/NodeApi/JSValueScope.cs:349-355`, `:399`); on the Bun side one `HandleScopeImpl` GC cell per call and a locked append per object argument (`bun:system/jsc/bindings/napi_handle_scope.cpp:67-71`, `:121-142`, `bun:NapiClass.cpp:67`).
2. **Property access by name**: new JS string + `napi_get_property` on every `value["x"]` (`nad:JSValue.cs:114-118`, `:560-562`); Bun's `node_api_create_property_key_*` makes no atom (`bun:napi.cpp:1525-1550`).
3. **Implicit v8 semantics**: neither the generated module nor `NativeHost` exports `node_api_module_get_api_version_v1` (`nad:ModuleGenerator.cs:294-298`, `nad:NativeHost.cs:184-187`) ⇒ v8 under Bun and Node (`bun:BunProcess.cpp:798-802`, `node:src/node_version.h:118`): `napi_ref` rejected on primitives (`bun:napi.cpp:1113-1118`).
4. **TSFN fairness**: unlimited queue (`nad:JSSynchronizationContext.cs:267-273` `maxQueueSize: 0`) and Bun drains the whole queue in one tick (`bun:napi_body.rs:2721-2791`) whereas Node caps at 1000 (`node:src/node_api.cc:409`, `:570`).
5. **Leak on TSFN abort**: `CustomCallJS`/`DefaultCallJS` return on a null `env` without releasing the data's `GCHandle` (`nad:src/NodeApi/Interop/JSThreadSafeFunction.cs:227-230`); Bun does hand the remaining items back with a null env (`bun:napi_body.rs:2968-2985`).
6. **No net11 and no Bun in CI**: TFMs `net10.0` at most (`nad:Directory.Build.props:3-11`), SDK `10.0.303` (`nad:global.json`), hard-coded test runtime `node --expose-gc` (`nad:test/TestBuilder.cs:306-312`, `nad:test/JSProjectTests.cs:171`). On the Bun side, no compiled addon in the Windows CI (`bun:test/expectations.txt:20-24`).
7. **Cross-GC cycles**: JS wrapper → strong `GCHandle` → .NET object → strong `JSReference` → wrapper: leak (no bridge; the only runtime bridge, `JavaMarshal`, is Android: `rt:CoreLib/Java/JavaMarshal.Unsupported.cs:20`).
8. **bun:ffi**: no struct by value, no varargs, no UTF-16 string type, unspecified returns of threadsafe `JSCallback`, `ptr`/`read.*` without intrinsic (`bun:abi_type.rs:15-49`, `bun:ffi_body.rs:1844-1963`, `bun:system/jsc/bindings/ZigGeneratedCode.cpp:9-28`); types and call in the prebuilt WebKit (`bun:scripts/build/deps/webkit.ts:4-6`).
9. **Home-grown hostfxr discovery** (`nad:src/NodeApi/DotNetHost/HostFxr.cs:56-70`, TODO to port `nethost.cpp`) instead of `get_hostfxr_path` (`rt:src/native/corehost/nethost/nethost.h:91-94`).
