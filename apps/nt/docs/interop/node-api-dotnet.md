C binding: each method keeps a static function pointer resolved lazily on first use (`NodeJSRuntime.cs:35-44`, name captured by `[CallerArgumentExpression]`) through `NativeLibrary.GetExport(_libraryHandle, name)` (`:27-28`). The default handle is `NativeLibrary.GetMainProgramHandle()` (`:18-21`): **the napi symbols must be exported by the host executable** (node.exe, bun.exe); no import link to `node.lib`. `IsAvailable()` = `TryGetExport` (`:24-25`), used to detect features (e.g. TSFN, `JSThreadSafeFunction.cs:32-33`). netstandard/net472 shim: `Runtime/NativeLibrary.cs:25-33` (`GetModuleHandle(NULL)` / `dlopen(NULL)`).

Function pointers vs delegates: `UNMANAGED_DELEGATES` is defined except for doc generation (`Directory.Build.props:82`); callbacks are then `delegate* unmanaged[Cdecl]` to `[UnmanagedCallersOnly]` methods (`JSValue.cs:1230-1255`), otherwise delegates kept in static fields (`:1216-1229`).

## 2. Value model

- `JSValue` = `readonly struct { napi_value _handle; JSValueScope? _scope; }` (`JSValue.cs:18-21`). `default` = `undefined` (`:31-35`, `:94`).
- Every access to `Handle` checks the scope: `ThrowIfDisposed()` + `ThrowIfInvalidThreadAccess()` (`JSValue.cs:69-86`); the latter compares the `env` of the current thread-static scope (`JSValueScope.cs:95-96`, `[field: ThreadStatic] CurrentOrNull`) with that of the value (`:442-448`).
- `JSValueScopeType`: `NoContext`, `Root`, `Module`, `Callback`, `Handle`, `Escapable` (`JSValueScope.cs:16-54`). Only `Handle`/`Escapable` open a `napi_handle_scope` (`:314-323`); `Callback` relies on the implicit scope of the napi call. `Root`/`Callback` install the JS `SynchronizationContext` on entry and restore it on exit (`:349-355`, `:399`).
- AOT: no `Root` scope; each module has its `JSRuntimeContext` (`JSValueScope.cs:28-31`, `:250-262`: `Runtime = runtime ?? new NodejsRuntime()`).
- `JSRuntimeContext` is stored as the env's _instance data_ (`JSRuntimeContext.cs:152-161`, `JSValue.SetInstanceData`); it carries the class maps (`:58`, `:68`), structs (`:92`), imports (`:102`), collection proxies (`:114`) and the .NET object→JS wrapper identity (`:81`, `ConditionalWeakTable<object, JSReference>`).
- Strings: direct UTF-16 creation (`JSValue.cs:157-166`, implicit `string`→`JSValue` conversion `:1528`); reading in 2 napi calls (length then copy) into `string.Create` (`:515-531`). The copy passes `span.Length + 1` to write the NUL into the internal terminator of `string` (`:526-527`). Properties by name: `value["x"]` (`JSValue.cs:114-118`) first converts `string` → new JS string (`napi_create_string_utf16`) then `napi_get_property` (`:560-562`); that is 2 napi calls and one JS string per access, without key cache. `napi_get/set/has_named_property` are bound (`NodejsRuntime.JS.cs:1429-1451`, UTF-8 via `PooledBuffer`) but never called outside the runtime classes. Not imported: `node_api_create_external_string_*`, `node_api_create_property_key_*`.

## 3. Marshalling

A single engine, two back-ends:

- `JSMarshaller` builds `LambdaExpression`s per type/method: `BuildFromJSMethodExpression` (`JSMarshaller.cs:522`), `BuildFromJSConstructorExpression` (`:450`), `BuildToJSMethodExpression` (`:614`), properties (`:554`, `:584`, `:1129`, `:1197`), delegates (`:800`, `:938`), overloads (`:1263`, `:1353`). Conversions: `BuildConvertFromJSValueExpression` (`:2075`), `BuildConvertToJSValueExpression` (`:2422`), Promise↔Task (`:2771`, `:2843`), arrays (copy, `:2923`, `:2967`), structs (field-by-field copy, `:3000`, `:3040`), collections (proxies, `:3099-3520`).
- Handled types (`:2077-2400`): explicit operators of `JSValue` (primitives, string), `Nullable<T>`, enums, arrays, `Memory<T>`/`ReadOnlyMemory<T>` over typed arrays (`:2157-2190`), `KeyValuePair`, tuples, `DateTime`, `TimeSpan`, `DateTimeOffset`, `Guid`, `BigInteger`, `CancellationToken`, `Stream`, delegates, `Task`, collection interfaces, arbitrary interfaces.
- **JIT**: `LambdaExpression.Compile()` + `ConcurrentDictionary` cache (`:75-79`, `:304-359`); JS interfaces implemented in .NET through `TypeBuilder`/`ILGenerator` (`JSInterfaceMarshaller.cs:52-512`); dynamic assembly (`JSMarshaller.cs:3938`).
- **AOT**: the Roslyn generator converts symbols into symbolic `Type`s (`SymbolExtensions.cs:34-86`, in-memory `AssemblyBuilder` in the compiler), calls the same `JSMarshaller` (`ModuleGenerator.cs:29-33`, `:610-805`) then serializes each tree to C# through `ExpressionExtensions.ToCS` (`ExpressionExtensions.cs:29`, `ModuleGenerator.cs:1041-1055`). The AOT code therefore runs the same conversion logic, compiled statically.
- Copy-free typed arrays: `JSTypedArray<T>(Memory<T>)` reuses the original JS array if the memory comes from it, otherwise pins the .NET memory (`Memory.Pin()`) and creates an external `ArrayBuffer` (`JSTypedArray.cs:108-123`, `JSValue.cs:252-264`, `PinnedMemory` `:1462-1500`). In the other direction, `JSTypedArray<T>.Memory` exposes the JS memory through a `MemoryManager<T>` that assumes a non-movable buffer (`JSTypedArray.cs:286`, `:332-359`, comment `:355-356`).
- Exported .NET classes: `napi_define_class` + `napi_wrap` of a `GCHandle` (`JSValue.cs:788-860`); a .NET object returned to JS is rewrapped through the JS constructor of the class with an `external` (`JSRuntimeContext.cs:343-367`).
- `.d.ts`: `TypeDefinitionsGenerator` reads the compiled assembly through `MetadataLoadContext` (`TypeDefinitionsGenerator.cs:213`, `:261`, `:419`).

## 4. Threading

- Rule: every JS API on the JS thread, otherwise `JSInvalidThreadAccessException` (`docs/features/js-threading-async.md:3-15`, `JSValueScope.cs:442-448`).
- `JSSynchronizationContext.Create()` picks TSFN if `napi_create_threadsafe_function` is exported, otherwise `JSDispatcherQueue` (embedding context) (`JSSynchronizationContext.cs:42-55`).
- `JSTsfnSynchronizationContext` (`:252-400`): one TSFN `maxQueueSize: 0`, `initialThreadCount: 1`, immediately `Unref()`'d so it does not block exit (`:267-273`); `napi_add_env_cleanup_hook` hook registered after the TSFN to release it before the libuv handle is closed (`:274-284`). `Post` = `NonBlockingCall` (`:358-368`); `Send` = `NonBlockingCall` + `ManualResetEvent.WaitOne()` (`:372-400`). `TsfnCallGate` prevents a call concurrent with the release (`TsfnCallGate.cs:8-11`).
- `JSThreadSafeFunction`: each call allocates a `GCHandle` (+ closure) released by the JS callback or on failure (`JSThreadSafeFunction.cs:174-190`); `napi_queue_full` / `napi_closing` are swallowed (`:183-189`). `Ref/Unref/Release/Abort` (`:131-171`).
- Task↔Promise: `AsTask` (`TaskExtensions.cs:14-57`), `AsPromise` (`:95-137`); continuations come back on the JS thread through the context installed by each `Callback` scope.
- Workers: `NodeWorker` wraps `node:worker_threads` (`NodeWorker.cs:20-25`, `:120`); several managed hosts possible (one `Root` scope per worker, `JSValueScope.cs:205-214`).

## 5. Lifetime / GC

- JS → .NET: normal (strong) `GCHandle` stored in `napi_wrap`/`napi_create_external`/function `data`; released by the napi finalizer `FinalizeGCHandle` (`JSValue.cs:1380-1396`), `IDisposable` variant (`:1398-1421`) and pinned memory (`:1423-1440`). Counter and handle map for diagnostics (`JSRuntimeContext.cs:732-797`).
- .NET → JS: `JSReference` (`napi_ref`, strong or weak; `JSReference.cs:71-103`, `:181-198`). Explicit `Dispose()`: direct deletion or posted to the JS thread (`:373-397`). .NET finalizer (`:530-537`): never throws; post to the JS thread if a context exists, otherwise queue `s_pendingFinalizerDeletions` drained at the creation of the next scope on that thread (`:36-56`, `:400-460`, `:478`, `JSValueScope.cs:362-366`).
- Identity: `ConditionalWeakTable<object, weak JSReference>` (`JSRuntimeContext.cs:81`, `:304-341`). A JS wrapper keeps the .NET object alive (strong GCHandle); the .NET object only keeps a weak reference to the wrapper. **No cross-GC cycle tracking**: a .NET object holding a strong `JSReference` to a JS object that references it leaks (nothing in the code links the two GCs, neither `IReferenceTracker` nor an equivalent).
- `CallFinalizeAction` still creates a JS scope in a finalizer, marked TODO since it is eventually forbidden (`JSValue.cs:1442-1460`). No module exports `node_api_module_get_api_version_v1` (empty rg): finalizers therefore follow the "legacy" semantics of the host runtime.

## 6. Module registration

- AOT: the generator emits `[UnmanagedCallersOnly(EntryPoint = "napi_register_module_v1")]` (`ModuleGenerator.cs:27`, `:294-298`) that creates a `Module` scope never released (parent of the callbacks, `:290-305`) then exports the `[JSModule]` class or the `[JSExport]` members through `JSModuleBuilder<T>` (`:364-393`); error → `JSError.ThrowError` (`:339-346`).
- JIT host: `NativeHost` also exports `napi_register_module_v1` (`NativeHost.cs:184-187`) and only exposes `initialize()`.
- AOT packaging: `PublishAot` ⇒ `PublishNodeModule`, `InvariantGlobalization`, `UseSystemResourceKeys` (`src/NodeApi/NodeApi.csproj:13-19`); `SelfContained` forced (`NodeApi.targets:24-33`); `.dll/.so` → `.node` rename (`:36-57`); the module JS script is rewritten to no longer depend on `node-api-dotnet` (`:2-22`).

## 8. Embedding (libnode)

`NodeEmbeddingPlatform` / `NodeEmbeddingRuntime` / `NodeEmbeddingThreadRuntime` load `libnode` (`NodeEmbedding.cs:96-139`) and import 27 `node_embedding_*` functions (`platform_create`, `runtime_create`, `runtime_event_loop_run[_once|_no_wait]`, `runtime_node_api_scope_open/close`, `runtime_config_set_task_runner`, ...; `NodejsRuntime.Embedding.cs`). `NodeEmbeddingThreadRuntime` dedicates a thread and pumps the loop (`NodeEmbeddingThreadRuntime.cs:24`, `:70`). The bench README requires a "special branch build of `libnode`" (`bench/README.md:7`). On the Bun side (`oven-sh/bun` fork @ `4b8463ee`), the export lists `system/symbols.def` and `system/symbols.txt` only contain Node-API, libuv, part of the V8 C++ API (decorated names) and `node_module_register`: no `node_embedding_*` type of embedding API. This path (.NET hosting JS) therefore does not apply to Bun without a patch.

## 9. Critical performance paths (JS → .NET)

Per call (`JSValue.cs:1259-1266`, `:1356-1376`, `JSCallbackArgs.cs:20-60`, `:75-84`):

1. `new JSValueScope(Callback)`: **allocation of a class** + parent checks + `SetSynchronizationContext` ×2 + `DrainPendingDeletions` (`JSValueScope.cs:71`, `:349-366`).
2. `napi_get_cb_info` ×2 (length + data, then args + this) and `GCHandle.FromIntPtr(data).Target`.
3. `stackalloc napi_value[argc]`; `JSCallback` delegate of the descriptor; per-argument conversions (1+ napi call each, e.g. `napi_get_value_double`); result → 1+ napi call.
4. Each napi call = virtual `JSRuntime` call + function pointer + scope/thread checks on every `JSValue.Handle`.
5. .NET exceptions → `JSError.ThrowError` (`JSError.cs:271`).

Vendor figures (not measured here): "warm" call 54 µs JIT / 47 µs AOT vs 23 µs pure JS, average of 10,000 calls passing a medium object (`docs/features/performance.md:11-20`; l.11 says "JS to .NET", l.20 ".NET -> JS": direction ambiguous in the source). BenchmarkDotNet benches in `bench/Benchmarks.cs:151-269`, dependent on a special libnode.

## 10. What matters for Bun

- Hard dependency: `napi_*` symbols exported by the host exe (`NodeJSRuntime.cs:18-28`) and TSFN (`JSSynchronizationContext.cs:42-55`).
- "Node" functions imported: `napi_get_uv_event_loop`, async work, cleanup hooks (async included), `napi_adjust_external_memory`, type tags, instance data, `node_api_get_module_file_name`, `node_api_symbol_for`, `node_api_create_syntax_error` (`NodejsRuntime.JS.cs` / `.Node.cs`). But `CreateAsyncWork`/`QueueAsyncWork`/`GetUVEventLoop`/`AdjustExternalMemory`/`AddAsyncCleanupHook` are called nowhere outside the runtime classes (rg on `src/`: only `JSRuntime.cs:442-450`, `NodejsRuntime.Node.cs:180`, `:499` and the pass-through `TracingJSRuntime.cs`); since binding is lazy (§1), their possible absence on the host breaks nothing. .NET `Task`s run on the .NET pool and come back through TSFN (§4).
- Effective surface: of the 138 `override` methods of `NodejsRuntime` (`.JS.cs` + `.Node.cs`), 110 are called by the rest of the library and 28 never (async work ×4, `AsyncInit/Destroy`, `MakeCallback`, `Open/CloseCallbackScope`, Node buffers ×5, `GetUVEventLoop`, `AdjustExternalMemory`, `Add/RemoveAsyncCleanupHook`, `GetModuleFileName`, `GetNodeVersion`, `FatalException`, `GetNewTarget`, `Get/Set/HasNamedProperty`, `ThrowTypeError/RangeError/SyntaxError`) — rg `\.<Method>(` outside `JSRuntime.cs`, `NodejsRuntime.*.cs`, `TracingJSRuntime.cs`.
- Bun coverage of the 140 symbols: all defined in `oven-sh/bun` (aphrody-labs fork @ `4b8463ee`), either in C++ `extern "C"` under `system/jsc/bindings/` (92 distinct names), or in `system/symbols.def` (142 names); empty diff (union vs imported list). On Windows the export goes through `NAPI_EXTERN` = `__declspec(dllexport)` (`system/runtime/napi/js_native_api.h:11-20`) plus `symbols.def`, checked by `scripts/build/binary-expectations.ts:590-612`.
- Implicit Node assumptions: reverse order of cleanup hooks (`JSSynchronizationContext.cs:274-277`), non-movable typed array buffers (`JSTypedArray.cs:355-356`), `require`/`import` passed by `init.js` (`:74-78`), `node:worker_threads` (`NodeWorker.cs:25`).
