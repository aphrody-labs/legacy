AUTO — STANDALONE SERVER

This package contains the runtime, the native library, the migrations and the
web/Craft resources. Keep and extract the whole folder. Bun, Node and a
JavaScript package manager are not needed on the target machine.

To simply use the Auto service, open https://auto.aphrody.com/app
or install the application from https://auto.aphrody.com/telechargements.

HOSTING YOUR OWN INSTANCE

1. Prepare a PostgreSQL database and its migration account. The initial
   migrations create the auto_app role: the account used must be allowed to do so.
2. Provide the environment variables below, with your own values.
   Do not publish your passwords or the master key. Keep this key stable so
   encrypted secrets can be read again after a restart.

   NODE_ENV=production
   DATABASE_URL=postgres://auto:PASSWORD@127.0.0.1:5432/auto
   AUTO_CLE_MAITRE=YOUR_RANDOM_KEY_OF_64_HEXADECIMAL_CHARACTERS
   AUTO_URL_APP=https://auto.your-domain.example
   AUTO_API_URL=http://127.0.0.1:3000
   AUTO_BIND_HOST=127.0.0.1
   AUTO_SMTP_HOTE=smtp.your-domain.example
   AUTO_SMTP_PORT=587
   AUTO_SMTP_SECURITE=starttls
   AUTO_SMTP_UTILISATEUR=auto@your-domain.example
   AUTO_SMTP_MOT_DE_PASSE=YOUR_SECRET

   On Linux, use export NAME=value in the shell or your service manager.
   On PowerShell, use $env:NAME='value' in each terminal.

3. Run the migrations: ./auto migrate (Linux) or .\auto.exe migrate (Windows).
4. Start three separate processes, with the same environment:
   - PORT=3000: auto api
   - auto worker
   - PORT=3001: auto web
   On PowerShell, set $env:PORT='3000' or '3001' before the command.
5. Configure your HTTPS reverse proxy to the local front end on port 3001.
   The API and PostgreSQL stay on the private network. Sign-up creates a
   company; colleagues join it through the team invitations.

The master key, the real mail relay and the public URL are required in
production. Google/Microsoft OAuth, document storage, AI and external
integrations are configured separately. The OCR/conversion functions use
Chromium, Tesseract and Poppler when they need them; their executables
remain host dependencies. auto tools gives the available diagnostics.

VERIFICATION AND UPGRADE

SHA256SUMS.json contains the fingerprints of the package files. Also compare
the SHA-256 of the archive with the public catalog before extraction. Back up the
database and the documents before a new version; going back to an older binary
does not restore a schema that was already migrated. The services must be
supervised and restarted with their private environment kept.
