Owner direction (2026-11-15): `ay` is the Bun binary built from the fork `aphrody-labs/bun` (Bun's own CLI), first-party features are cargo-feature modules, no feature lost; steam/epic/gaming/tv/craft are ecosystem consumers, their subcommands stay until another agent gives them entry points. Inventory: `infra/ay/modules.toml`, `scripts/ay-inventory.ts --check`, `docs/ay/MODULES.md`; extensions: `docs/ay/EXTENSIONS.md`.

**Why:** the owner wants a universal runner (JS/TS, bash, Rust scripts) that is Bun, not a Rust CLI with Bun crates linked in.

**How to apply:**
- Fork code of ours lives in `src/modules` (bun_modules: applets.rs generated by `scripts/ay-modules-gen.ts` with live uutils revs, bash.rs on rubash from a git dep of the monorepo, binutils.rs, script.rs). Hooks: `src/runtime/bin_entry/mod.rs` (argv[0] multicall, `applet NAME`), `src/runtime/cli/run_command.rs` (`run_other_language`).
- Bun's build has no no-JSC mode: bun_runtime links JSC always; only `--webkit=prebuilt|local`. bun_install depends on bun_js_parser/js_printer/transpiler (JS parser, not JSC).
- Bun's rust plan accepts only rlib libraries: a dep with cdylib/staticlib (crc_fast via uucore) needed the units.ts patch; `Cargo.lock` needed a full `cargo update` (uutils crates raise libc, regex-automata, hashbrown).
- A rebase of the fork on upstream compiled only after fixing a semantic conflict (upgrade_command.rs `Progress::root()`); rebase with `remote.upstream.promisor=true` on blob:none clones.
- Build on fr1 as a systemd unit (`sudo systemd-run --uid=ubuntu ...`): processes started by plain ssh/nohup/setsid got killed ("ninja: interrupted by user"). fr2 disk was full (96G) on 2026-11-16: rustup auto-install of the fork's toolchain targets filled it; use `RUSTUP_TOOLCHAIN=nightly-2026-09-15`.
- scp does not work from the PC; pipe through `ssh host 'cat > f' < local`.
